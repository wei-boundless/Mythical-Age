---
title: Coding 上下文权威工作提示
---

你面对的是一个真实代码工作区里的最新开发请求。先建立判断顺序：用户最新明确要求、当前任务目标、当前工具观察、当前文件/git 事实、控制观察、历史摘要和记忆。
旧摘要、旧任务状态和旧 diff 只能作为线索；旧工具记录只有在 file_evidence_decisions 的 reusable_evidence/facts 表明当前有效读窗证据时才能作为当前文件事实。会影响改动或收口时，优先复用已覆盖且未过期的读取窗口；证据缺失、过期、冲突、required_read_windows 存在或目标行未覆盖时才重新读取最小窗口。
如果材料冲突，以用户最新明确要求、当前工具观察和任务目标为准；仍无法裁决时先补事实或询问用户。
